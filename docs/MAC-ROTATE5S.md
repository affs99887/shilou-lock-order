# 拾漏锁单 Mac 代理 5 秒版

版本：0.6.2-rotate5s.2，基于 0.6.2-minute.7。

## 解决什么问题

Apple 按「出口 IP」（你的网络在 Apple 看来的地址）和「会话」（cookie）累计库存查询次数：同一个 IP 连续查大约 30 次就会被拦（HTTP 541），之后十几分钟一直被拦。所以 5 秒一次的版本（0.6.2-quiet5s.1）用着用着就查不动了，0.6.2-minute.7 只好退回 60 秒。

本版把查询分散到多个代理的 IP 上，并且不再占用本机网络，间隔才能调到 5 秒。

## 三种查询方式

在「手机提醒」页的「代理线路」里选：

- **本机网络**：固定每 60 秒查一次；填了代理时和代理轮流用。和 0.6.2-minute.7 一样。
- **代理轮流（机场节点）**：只用代理。每个代理是一个固定出口，各自留 cookie、各自算请求额度。被 Apple 拦截（541）的代理单独暂停 5、10、20、30 分钟逐档延长，到期只放一次试探请求；连不上的代理先暂停 30 秒，接连失败延长到 5 分钟。其余代理照常查询。
- **隧道代理（每次换 IP）**：只用代理。每次查询都新建连接和 cookie，代理商随之换一个出口 IP；某个 IP 被拦就当场换 IP 重查。代理要选「按请求换 IP」的。

后两种不走本机网络，本机网络留给自动选购用的浏览器，查询间隔可选 5～60 秒。一次查询最多试 3 条线路（隧道代理是 3 个 IP），避免一口气把所有 IP 都撞一遍。

## 用机场节点

1. 安装 PyYAML（`pip3 install pyyaml`），用订阅文件生成专用的 Mihomo 配置：

   ```bash
   python3 scripts/apw-mihomo-config.py ~/Downloads/订阅.yaml
   ```

   每个节点一个本地端口（18001 起），同时生成 `apw-mihomo.yaml`（含节点密码，不要外传）和 `apw-代理地址.txt`（只有本机端口）。要再排除某些节点，加 `--exclude '阿根廷|俄罗斯'`。

2. 下载 [Mihomo](https://github.com/MetaCubeX/mihomo/releases)（Apple 芯片选 `mihomo-darwin-arm64-版本号.gz`，解压后 `chmod +x`），启动后保持终端窗口开着：

   ```bash
   ./mihomo-darwin-arm64-v1.19.33 -d ~/.apw-mihomo -f apw-mihomo.yaml
   ```

3. 「代理线路」里粘贴 `apw-代理地址.txt` 的全部内容，选「代理轮流（机场节点）」，间隔选 5 秒，保存。

平时用的 Clash 保持规则模式，不要开全局：浏览器访问 apple.com.cn 要走本机网络，自动选购才不受影响。

## 登录

- 「选购方案」面板里有「登录 Apple 账户」按钮：打开 Apple 账号页，在弹出的浏览器窗口登录；确认已登录后自动结束，不加购。开售前先登录好，结账时少一步。
- 结账中途 Apple 要求登录时：推送「Apple 需要登录」，之后每 5 分钟再提醒一次，最多等 30 分钟。登录完回到购物袋或结账页会**自动接着结账**，不用点「继续」；已经做过的加购、改数量等操作不会重复执行。

## 登录后联系人页没有邮箱框

登录 Apple 账户后，官网的取货联系人页可能不显示邮箱输入框。这时只要姓名、手机号、证件后四位都和保存的资料一致，页面上又只有一个「继续选择付款方式」按钮，就接着往下走。到订单核对页再看邮箱：

- 核对页上的邮箱和保存的一致：照常继续。
- 整个核对页都没显示邮箱：其余都核对一致就照常继续；开了自动下单会自动点「立即下单」，邮箱按官网登录的账户。
- 显示的邮箱和保存的不一致，或者有多个邮箱：停下，不下单，等你核对。

提交前会重新读一次页面，邮箱再核对一遍。自动选购、手动开始选购、测试演练和库存表「立即选购」都按这个规则。

## 手动开始选购

监控出问题时的备用入口，在「自动选购」面板里：

1. 在「选购目标」下拉框选一行监控目标。型号、颜色、容量按这一行；这一行的门店是**指定门店**，取货地区也按它填。
2. 点「手动开始选购」。不等监控，也不需要监控显示有货，直接打开官网开始选购。
3. 到选门店那一步：指定门店能取货就选它；不能取货（选项不可点、写着不可取货，或者没有你设定的取货日期、没有签到时段），就按官网列表顺序改选**同城**下一家能取货的门店。别的城市的门店不会选。同城都不能取货时，这次自己结束并推送「手动选购没买到」，不用点停止。
4. 后面的联系人、付款、核对和测试演练一样。方案里开了「自动下单，等待本人支付」时，点按钮就直接开始，不再弹窗确认，到核对页会自动点「立即下单」；没开就停在提交前，由你本人下单。

和测试演练的区别：可以自动下单；会改选同城门店。和测试演练一样的地方：只试一次，不循环；官网明确没货、超预算或还没开卖时，这次自己结束，状态行写明原因；运行时间最多 5 分钟，等你登录或验证的时间不算在内。

自动选购开着、正在等库存时也能点「手动开始选购」或「测试演练」：自动选购先暂停，这次结束后自动恢复，不管是自己结束还是你点「结束本次选购」。只有三种情况不恢复：这次走到过订单核对页（你可能已在官网手动下单，免得再自动买一台）、有未核对的下单记录、官网拒绝过访问。不恢复时状态行会写明原因，需要时再点「启用有货自动选购」。

按钮跟着状态变：空闲时是「启用有货自动选购」「手动开始选购」「测试演练」；自动选购开着时第一个按钮变成「停止自动选购」；有选购在跑时只剩「结束本次选购」（自动选购的单子是「停止自动选购」或「停止选购」），需要你处理而暂停时再多一个「人工处理后继续」。

需要你处理而暂停时（比如登录、验证），如果你在 Safari 里刷新了门店列表，点「人工处理后继续」会重新判断每家门店。换型号或换城市，就先点「结束本次选购」，在下拉框换一行，再点「手动开始选购」。

## 开售前显示「未开放」是正常的

新品开售前，Apple 对还没开放到店取货的型号返回 `default`。这时库存显示「未开放」，鼠标停上去写着「Apple 暂未开放这款在该店的到店取货」。它不算查询异常，也不会拉长查询间隔；开放后会自动变成有货或无货。

## 出问题时会怎样

- 选购时官网显示「找不到页面」：隔 1 秒、3 秒各自动重开一次购物袋，只重开软件自己开的标签页，不重复删除或加购；已经加购的回到购物袋后接着结账。两次都打不开，单次选购自己结束并写明原因，自动选购等下一次有货再试。

- 某个节点被 Apple 拦截：这个节点自动暂停，其余节点继续查。被拦的节点越来越多时，界面提示「库存查询受阻」，建议换一批节点。
- 某个节点连不上：自动暂停一会儿再试。
- Mihomo 没在运行，或代理全部连不上：库存显示「未知」，原因写着连不上哪个代理。**不会改用本机网络**，以免把本机 IP 也搭进去。
- 连续 3 分钟一个结果都查不到：通过系统通知、Bark 和飞书推送「监控受阻，可能错过有货」；恢复后再推送「库存监控已恢复」。
- 自动选购的页面被 Apple 拒绝（541 / 403 / 429）：仍按原规则暂停监控，本版没改这条。

## 需要知道的限制

- 不能保证一定不被拦。机场 IP 多人共用，有些节点可能一开始就已经被 Apple 拦了；软件会把它们暂停，但可用的 IP 会变少。
- 每个节点第一次用时会多打开一次购物袋页拿 cookie，所以刚开始几十秒的查询间隔会比 5 秒长一些。

命令行版同样支持：`apw watch ... --proxy <地址> --proxy-mode pool --interval 5`，见 [cli.md](cli.md)。

构建前运行 `python3 scripts/mac-source.py`，再运行 `npm run tauri -- build --bundles app -- --locked`。
